# 如何模拟真实用户行为：拟人化设计全解

> 本项目的目标不是「绕过平台检测」，而是**把自动化操作做到像真人求职**：
> 真的在看 JD、真的在比较、节奏有快有慢、绝不群发。以下是全部设计与
> 默认参数。**请不要调低这些值**——它们既是平台友好性的底线，也是你
> 账号安全的第一道防线。

## 1. 滚动行为：像人在浏览列表

`human_read_scroll()`（run_pipeline.py）：

- **步长随机**：每轮从 `[260, 380, 520, 700, 900, 1100]` px 中随机取一个，不做匀速机械滚动；
- **停顿随机**：每次滚动后停 1.2–3.6 秒；
- **28% 概率回滚** 120–320px——像真人在「往回比较」两条岗位。

## 2. 岗位详情页：先看 JD，再点沟通

`send_one()`（run_pipeline.py）每条岗位的完整节奏：

```
打开详情页 → 停 3.0–5.5s（像在等页面+读标题）
→ 风控体检（只扫平台告警区，不扫 JD 正文）
→ 抓 JD 文本（英语要求检查 + 给 AI 写话术用）
→ 滚动 260–620px「扫一眼 JD」→ 停 1.0–2.6s
→ 点「立即沟通」→ 停 1.0–1.8s
→ 处理可能弹出的额度提示 → 停 2.2–3.8s
→ 进聊天页 → 停 3.0–5.0s → 填定制话术 → 停 0.8–1.8s
→ 点发送 → 停 1.8–3.0s → 回详情页核验按钮状态
```

## 3. 批量节奏：快慢交替，绝不匀速

| 机制 | 默认值 | 含义 |
|---|---|---|
| 岗位间隔 | `pause(4.0, 9.0)` | 每条岗位之间随机 4–9 秒 |
| 长休息 | 每发 **4** 条（`--rest-every`）休息 25–70s | 「模拟真人离开」（去倒了杯水） |
| 周期冷却 | 15–40s | 流水线每周期（收2块+发4条）之间 |
| 限流冷却 | 连续 5 条发送失败 → 300–480s 后收手 | 疑似平台限流：长冷却，且**失败不进跳过池**，保留后续自动重试机会 |
| 搜索块间隔 | 块间 3–7s（流水线）/ 1–1.5s（刷池） | 换一个「城市×关键词」时的停顿 |

## 4. 顺序随机化

- **城市 × 关键词乱序**：搜索队列构建时 `random.shuffle`，同一天两轮的遍历顺序不同；
- **候选排序天然多样**：频道岗位优先、档位顺序、priority 词、标题长度——不是按列表页顺序机械往下投。

## 5. 话术：单条定制，杜绝群发痕迹

这是最重要的拟人化——**行为再像真人，发出去的内容一眼群发就全完了**：

- **AI 逐条读 JD 现场撰写**（`messages.json`），没有话术的岗位直接跳过（默认不发模板兜底，`--allow-template` 才开启且不推荐）；
- 写作规范（`profile.json → ai_message_rules`）强制：必须引用该岗位 JD 的具体内容（业务场景/技术栈/职责关键词）、素材只能来自你的真实 resume_points、每条只展开 1–2 项最相关经历、结尾统一一句「期待和您聊聊。」、**同批话术的开头/句式/结构必须互不重复**、单条 ≤250 字；
- 发送前先过 **英语过滤**（JD 要求英语作为工作语言的岗位直接跳过，不点沟通、不产生触达）——对英语岗发中文话术是典型的「AI 痕迹」。

## 6. 频率与额度的自我约束

- **不给自己预设每日额度**（`--target 0` 默认）：让平台的额度规则说了算，而不是顶着平台限制硬投；
- **三态额度弹窗处理**：软提醒「还剩N次机会」→ 关掉后**必须重发**；「今天投递数量达到N个，是否继续」→ N<150 点「继续投递」；真封顶「您已达到沟通上限」→ 当日优雅收工；
- **静默封顶识别**：连续 12 条岗位连招呼语都发不出去（无确认框）→ 读页面原文留证后收尾，不无限空转重试；
- **风控双保险**：进页与滚动后各体检一次（只扫弹窗/提示条/验证页等**告警区**，不扫 JD 正文，避免「数据爬取」这类 JD 常用词误伤熔断）；流水线启动前有 **30 分钟风冷却守卫**（`--risk-guard-min`），刚触发过风控就拒绝启动；
- **单实例锁**：`run.lock` 防止并发运行重复投递（实测并发出过 22 条重复）。

## 7. 一句话原则

> 宁可慢、宁可少、宁可跳过，也不发出任何一条「一看就是机器发的」消息。

所有参数在代码里都收敛为 `pause(a, b)` 或带默认值的 CLI 参数，理论上你可以调，
但**调低的每一秒都在把风险转嫁给你的账号**。如果确实想更保守，调高的方向是
安全的：`--rest-every 3`（每 3 条就长休息）、`--per-cycle 2`（每周期只发 2 条）。
